# 스킬 테스트 가이드

하네스가 생성한 스킬은 작성 후 반드시 테스트하고 반복 개선한다.

## 기본 루프

```text
작성 -> 테스트 실행 -> 평가 -> 수정 -> 재테스트
```

## 1. 테스트 프롬프트 작성

테스트 프롬프트는 실제 사용자 요청처럼 써야 한다.

권장:

- 핵심 사용 사례 1개
- 엣지 케이스 1개
- 필요하면 복합 작업 1개

## 2. With-skill vs Baseline

가능하면 같은 요청을 두 방식으로 비교한다.

- with-skill: 스킬을 읽고 수행
- baseline: 스킬 없이 같은 요청 수행

이 비교는 스킬이 실제로 품질을 높였는지 확인하는 데 유용하다.

## 3. Assertion 기반 검증

객관적으로 검증 가능한 작업은 assertion을 만든다.

좋은 assertion:

- 참/거짓 판정이 분명하다
- 스킬의 핵심 가치를 검증한다

나쁜 assertion:

- 결과가 존재하기만 하면 통과
- "잘 작성되었다"처럼 주관적임

## 4. Trigger 검증

description이 실제로 적절한 요청에서 선택될지를 점검한다.

- should-trigger 예시 8~10개
- should-NOT-trigger 예시 8~10개

near-miss 예시를 꼭 포함한다.

## 5. 반복 개선 원칙

- 피드백을 원리 수준으로 일반화한다.
- 무게만 늘리는 규칙은 제거한다.
- 반복 코드가 드러나면 번들링한다.

## 6. 워크스페이스 구조 예시

```text
{skill-name}-workspace/
├── iteration-1/
│   ├── eval-a/
│   └── eval-b/
└── iteration-2/
```

iteration을 분리해 두면 이전 결과와 쉽게 비교할 수 있다.
