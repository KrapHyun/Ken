# 스킬 작성 가이드

하네스가 생성하는 스킬의 품질을 높이기 위한 보조 가이드다.

## 1. Description 작성

description은 스킬의 핵심 트리거 문장이다. 다음 두 가지를 반드시 넣는다.

- 스킬이 하는 일
- 어떤 요청에서 반드시 써야 하는지

좋은 예:

```yaml
description: "PDF 읽기, 표 추출, 병합, 분할, 회전, OCR 같은 PDF 작업을 처리한다. .pdf 파일이나 PDF 산출물이 언급되면 이 스킬을 사용한다."
```

나쁜 예:

```yaml
description: "PDF 관련 작업"
```

## 2. 본문 스타일

- Why를 설명한다.
- 명령형으로 쓴다.
- 한 예시에 과적합하지 않는다.
- 불필요한 장문 설명은 references로 내린다.

## 3. Progressive Disclosure

권장 구조:

```text
skill-name/
├── SKILL.md
├── references/
├── scripts/
└── assets/
```

운영 규칙:

- 본문이 길어지면 세부 규칙은 `references/`로 이동한다.
- 반복 코드가 보이면 `scripts/`로 번들링한다.
- 출력 템플릿이나 샘플 파일은 `assets/`에 둔다.

## 4. 출력 형식 정의

산출물 형식이 중요하면 짧은 템플릿을 넣는다.

```markdown
## 보고서 구조
# 제목
## 요약
## 핵심 발견
## 권장 사항
```

## 5. 스크립트 번들링 기준

다음이 반복되면 `scripts/`로 옮긴다.

- 동일한 보조 스크립트를 여러 테스트에서 계속 다시 작성함
- 같은 설치/전처리 절차가 계속 반복됨
- 검증용 assertion 코드가 반복됨

## 6. 포함하지 않을 것

- 사용자용 장문 README를 스킬 내부에 중복 생성하지 않는다.
- 생성 과정의 메타 기록을 스킬 본문에 넣지 않는다.
- 모델이 이미 아는 일반 지식을 길게 복붙하지 않는다.
