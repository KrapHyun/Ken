# QA 에이전트 가이드

QA 역할의 핵심은 단순 존재 확인이 아니라 경계면 교차 비교다.

## 가장 흔한 결함 패턴

| 경계면 | 예시 |
|--------|------|
| API 응답 -> 프론트 훅 | 응답 shape와 기대 타입이 다름 |
| 파일 경로 -> 링크 | 실제 파일 경로와 href가 어긋남 |
| 상태 전이 맵 -> 실제 코드 | 정의된 상태 전이가 코드에서 누락됨 |
| DB/API/UI 필드명 | snake_case와 camelCase가 섞여 불일치 |

## QA 원칙

1. 한쪽만 읽지 말고 양쪽을 동시에 읽어라.
2. "존재한다"보다 "계약이 일치한다"를 검증하라.
3. QA는 마지막 한 번이 아니라 각 모듈 직후 점진적으로 실행하라.
4. 수정까지 포함하면 `worker`, 읽기/재현 중심이면 `default`를 고려하라.

## 통합 정합성 체크리스트

### API -> 소비자

- [ ] API 응답 shape와 소비자 타입이 일치하는가
- [ ] 래핑 응답이면 소비자가 unwrap 하는가
- [ ] 즉시 응답과 최종 결과 shape를 혼동하지 않는가

### 라우팅

- [ ] 코드 안의 링크가 실제 페이지 경로와 맞는가
- [ ] route group이나 동적 세그먼트를 고려했는가

### 상태 전이

- [ ] 상태 전이 표와 실제 업데이트 코드가 일치하는가
- [ ] 죽은 전이 또는 무단 전이가 없는가

## QA 역할 문서 템플릿

```markdown
---
name: qa-inspector
description: "통합 정합성과 경계면 버그를 점검하는 QA 역할"
---

# QA Inspector

## 핵심 역할
스펙 준수와 경계면 정합성을 검증한다.

## 작업 원칙
- 생산자와 소비자를 동시에 읽는다.
- 발견 사항은 파일과 라인 단위로 남긴다.

## 입력/출력 프로토콜
- 입력: 구현 파일, 스펙 문서, 테스트 결과
- 출력: `_workspace/30_qa_review.md`

## 협업 규칙
- 메인 오케스트레이터를 통해 재작업 요청을 전달한다.
```
